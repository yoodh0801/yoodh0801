```markdown
- **작성자:** 유동한

- **상태:** 초안 (Draft)
- **사전 지식:** Git 브랜치 생성 및 커밋(Commit) 기본 사용법
- **대상 독자:** 버전 관리 시스템을 처음 접하는 개발자
- **목표 :** 작업이 완료된 브랜치를 안전하게 기준 브랜치(`main`)와 병합(Merge)하는 방법 습득
```

---

## 1. 사전 준비 (작업 마무리 및 동기화)
병합 시작 전 작업 브랜치의 변경 사항 전체 저장 및 기준 브랜치 최신화

1. **작업 브랜치 커밋 완료:** 작업 브랜치(`feature/브랜치명`)에 미커밋 수정 파일이 남지 않도록 전체 커밋(`Commit`)
2. **기준 브랜치(`main`)로 이동:** GitHub Desktop 상단 **`Current branch`** 탭 클릭 후 병합 대상 브랜치(`main`)로 전환
3. **최신 코드 반영:** 우측 상단 **`Fetch origin`** (또는 `Pull origin`) 클릭으로 원격 저장소 최신 코드 다운로드

## 2. GitHub Desktop에서 로컬 병합 실행
기준 브랜치(`main`)에 위치한 상태에서 작업 브랜치 변경 이력 병합

1. **병합 메뉴 실행:**
   - 상단 메뉴 바에서 **`Branch`** → **`Merge into current branch...`** 클릭 (단축키: `Ctrl + Shift + M` / Mac: `Cmd + Shift + M`)
2. **가져올 브랜치 선택:**
   - 팝업 창에서 병합할 작업 브랜치(`feature/브랜치명`) 선택
   - 하단 *"This will merge X commits from [브랜치명] into main"* 메시지 정상 표시 확인
3. **병합 확정:**
   - 파란색 **`Create a merge commit`** 버튼 클릭으로 로컬 병합 완료

## 3. 원격 저장소(GitHub) 반영 및 정리
로컬 PC 병합 결과 원격 저장소 업로드 및 사용 완료 브랜치 정리

1. **원격 저장소 업로드:** 상단 **`Push origin`** 버튼 클릭으로 병합된 `main` 브랜치 GitHub 반영
2. **작업 브랜치 삭제 (선택):**
   - 병합 완료 후 불필요해진 작업 브랜치는 상단 **`Current branch`** 목록에서 우클릭 → **`Delete...`** 선택으로 정리

## 4. 요약 치트시트 (한눈에 보기)
| 단계 | GitHub Desktop 실행 경로 | 설명 |
|---|---|---|
| **1. 기준 브랜치 이동** | `Current branch` → `main` 선택 및 `Pull origin` | 병합 대상 브랜치 이동 및 최신화 |
| **2. 병합 실행** | 메뉴 `Branch` → `Merge into current branch...` | 작업 브랜치 선택 후 `main`에 병합 |
| **3. 원격 반영** | `Push origin` 클릭 | 병합 결과 원격 저장소(GitHub) 업로드 |

## 5. 주의사항 (Best Practices)
- **병합 방향 주의:** 반드시 **결과를 받아들일 기준 브랜치(`main`)로 먼저 이동한 뒤** 가져올 작업 브랜치(`feature/...`) 선택 및 병합
- **미커밋 파일 확인:** 작업 브랜치에 미커밋 변경 사항 잔존 시 브랜치 전환·병합 오류 발생 가능성이 있으므로 항상 커밋 상태 선확인
