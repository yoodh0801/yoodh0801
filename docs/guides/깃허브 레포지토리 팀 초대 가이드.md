# GitHub Repository 팀 초대 가이드 문서

```markdown
- **작성자:** 유동한
- **최종 수정일:** 2026-11-26
- **상태:** 초안 (Draft)
- **사전 지식:** GitHub 계정 보유 및 저장소(Repository) 기본 이해
- **대상 독자:** 팀 프로젝트 협업 환경을 구성하려는 저장소 관리자
- **목표 :** GitHub 저장소에 협업자(Collaborator) 또는 팀(Team)을 초대하고 적절한 권한을 부여하는 방법 습득
```

---

## 1. 초대 전 확인 사항

원활한 권한 부여 및 협업 시작 전 저장소 소유 형태와 대상자 정보 확인

1. **저장소 소유 주체 확인:** 개인 계정(Personal) 소유 저장소인지 조직(Organization) 소유 저장소인지 확인
2. **초대 대상 정보 확보:** 초대할 팀원의 **GitHub 사용자명(Username)**, **가입 이메일 주소**, 또는 **Organization 내 팀(Team)명** 확인
3. **필요 권한 수준 검토:** 코드 읽기 전용, 브랜치 푸시·PR 작업, 저장소 설정 관리 등 팀원 역할에 맞는 권한 기준 수립

---

## 2. 개인 저장소 협업자(Collaborator) 초대

개인 계정 소유 저장소에 외부 또는 동료 개발자를 협업자로 추가

1. **저장소 설정 이동:** 대상 저장소 상단 탭에서 **`Settings`** 클릭
2. **협업자 메뉴 진입:** 좌측 사이드바 **`Collaborators`** 선택 (필요 시 GitHub 비밀번호 또는 2FA 인증 진행)
3. **초대 대상 검색:** **`Add people`** 버튼 클릭 후 초대할 팀원의 GitHub Username, Full name 또는 Email 입력
4. **초대 발송:** 검색 결과에서 대상 선택 후 **`Add [사용자명] to this repository`** 클릭
5. **초대 수락 안내:** 초대받은 팀원에게 이메일 또는 GitHub 알림 발송 및 **`Accept invitation`** 클릭 시 접근 권한 활성화

---

## 3. Organization 저장소 인원 및 팀(Team) 초대

조직(Organization) 소유 저장소에 개별 멤버 또는 팀 단위로 권한 할당

### 방법 A: 개별 협업자 추가
1. 대상 저장소 **`Settings`** → 좌측 **`Collaborators and teams`** 선택
2. **`Add people`** 클릭 후 Organization 멤버 또는 외부 협업자(Outside collaborator) 검색 및 선택
3. 역할(Role) 선택 후 초대 완료

### 방법 B: 팀(Team) 단위 권한 부여
1. 대상 저장소 **`Settings`** → 좌측 **`Collaborators and teams`** 선택
2. **`Add teams`** 클릭 후 저장소에 연결할 팀 선택
3. 팀 전체에 적용할 저장소 권한(Role) 지정 후 추가 완료

---

## 4. 저장소 권한(Role) 요약

팀원의 업무 범위와 보안 기준에 따른 주요 권한 단계 선택

| 권한(Role) | 주요 가능 작업 | 권장 대상 |
| :--- | :--- | :--- |
| **Read** | 코드 열람, 이슈 및 PR 조회·코멘트 작성 | 이해관계자, 외부 참고 인원 |
| **Triage** | 이슈·PR 라벨링, 담당자 지정, 닫기·재오픈 관리 | 이슈 트리아지·커뮤니티 운영 담당 |
| **Write** | 코드 푸시(`push`), 브랜치 생성·관리, PR 병합 | 일반 개발자, 핵심 기여 팀원 |
| **Maintain** | 저장소 설정 일부 관리(민감 설정 제외), 워크플로우 관리 | 프로젝트 리드, 릴리즈 관리자 |
| **Admin** | 저장소 삭제, 접근 권한 부여·회수, 보안·브랜치 보호 규칙 설정 | 저장소 소유자, 관리자 |

---

## 5. 요약 치트시트 (한눈에 보기)

| 단계 | 실행 위치 | 주요 작업 |
| :--- | :--- | :--- |
| **1. 설정 진입** | Repository → `Settings` | `Collaborators` 또는 `Collaborators and teams` 선택 |
| **2. 대상 추가** | `Add people` / `Add teams` | 사용자명·이메일·팀 선택 및 권한(Role) 지정 |
| **3. 초대 수락** | 초대 대상자 GitHub / Email | 초대장(`Accept invitation`) 수락 후 저장소 접근 시작 |

---

## 6. 주의사항 (Best Practices)

* **최소 권한 원칙 적용:** 실수로 인한 `main` 브랜치 강제 푸시나 설정 변경 방지를 위해 처음부터 `Admin` 부여 지양 및 `Write` 등 필요 권한부터 부여
* **초대 만료 기한 확인:** 발송된 초대 링크는 유효 기간(기본 7일) 경과 시 만료되므로 미수락 인원 재초대 필요
* **퇴사·이탈 인원 즉시 회수:** 협업 종료 또는 팀 이동 시 **`Collaborators`** 목록에서 **`Remove`** 클릭으로 접근 권한 즉시 회수
