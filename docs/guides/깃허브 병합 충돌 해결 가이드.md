## 1. 병합 충돌(Merge Conflict)이란?
- **정의:** 두 브랜치에서 **같은 파일의 동일한 위치(라인)**를 서로 다르게 수정 후 병합(Merge) 시도 시, Git의 자동 판단 불가로 개발자에게 코드 선택을 요청하는 상태
- **발생 원인:**
  - 팀원 A와 팀원 B가 동시에 같은 함수나 설정값을 각자 브랜치에서 수정한 경우
  - 내 작업 브랜치에서 수정 중인 파일을 다른 팀원이 먼저 `main` 브랜치에 병합한 경우

## 2. 충돌 발생 확인 (GitHub Desktop)
병합(`Merge into current branch`) 또는 최신화(`Pull origin`) 실행 시 충돌 발생 시 GitHub Desktop 안내 팝업 출력

1. **충돌 알림 확인:** *"Resolve conflicts before merging"* 메시지와 함께 충돌 파일 목록 및 개수(`X conflicted files`) 표시
2. **에디터 열기:** 충돌 파일 우측의 **`Open in Visual Studio Code`** (또는 기본 에디터) 버튼 클릭으로 파일 열기

## 3. 충돌 마커(Conflict Markers) 이해 및 코드 수정
에디터로 충돌 파일 오픈 시 특수 기호(마커)로 두 브랜치의 코드 병렬 표시

```text
<<<<<<< HEAD (Current Change)
const maxUsers = 100; // 현재 내 브랜치(기준 브랜치)의 코드
=======
const maxUsers = 500; // 가져오려는 브랜치(Incoming Change)의 코드
>>>>>>> feature/update-limit
```

- **`<<<<<<< HEAD` ~ `=======`:** 현재 위치한 브랜치(기준 브랜치) 코드 영역
- **`=======` ~ `>>>>>>> [브랜치명]`:** 병합하려 가져온 브랜치 코드 영역

### 해결 방법 (택 1)
1. **직접 수정 및 마커 제거:** 반영할 코드만 남기고(또는 조합 재작성) **`<<<<<<<`**, **`=======`**, **`>>>>>>>`** 기호 줄 전체 삭제
2. **VS Code 편의 버튼 활용:** 코드 상단의 **`Accept Current Change`**(현재 코드 선택), **`Accept Incoming Change`**(가져온 코드 선택), **`Accept Both Changes`**(둘 다 반영) 중 선택 클릭
3. **파일 저장:** 수정 완료 후 반드시 파일 저장(`Ctrl + S` / Mac: `Cmd + S`)

## 4. 충돌 해결 완료 및 병합 확정
모든 충돌 파일 수정 및 저장 후 GitHub Desktop 복귀 및 병합 마무리

1. **해결 상태 확인:** GitHub Desktop 팝업 창에서 모든 파일 우측 초록색 체크 표시(**`No conflicts remaining`**) 확인
2. **병합 커밋 실행:** 활성화된 파란색 **`Continue merge`** (또는 `Commit merge`) 버튼 클릭으로 병합 최종 확정
3. **원격 저장소 반영:** 상단 **`Push origin`** 버튼 클릭으로 해결 결과 GitHub 업로드

> **💡 병합 취소 방법:** 충돌 해결이 어렵거나 잘못 수정한 경우 팝업 하단 **`Abort merge`** 버튼 클릭으로 충돌 발생 직전 상태 복구 가능

## 5. 요약 치트시트 (한눈에 보기)

| 단계 | 실행 환경 | 주요 작업 |
|---|---|---|
| **1. 충돌 인지** | GitHub Desktop | 충돌 알림 팝업에서 `Open in [에디터]` 클릭 |
| **2. 코드 정리** | 코드 에디터 (VS Code) | `<<<<<<<`, `=======`, `>>>>>>>` 마커 제거 후 최종 코드 저장 |
| **3. 병합 확정** | GitHub Desktop | 초록색 체크 확인 후 `Continue merge` → `Push origin` 클릭 |

## 6. 충돌 예방 습관 (Best Practices)
- **수시로 최신 코드 동기화:** 작업 시작 전 또는 작업 중간에 기준 브랜치(`main`) 최신 변경 사항 수시 반영으로 코드 격차 최소화
- **작업 영역 분리:** 팀원 간 사전 작업 파일 및 기능 단위 명확한 분할로 동일 파일 동시 수정 상황 방지
