# Git 브랜치 생성 가이드 문서

```markdown
- **작성자:** 유동한
- **최종 수정일:** 2026-11-26
- **상태:** 초안 (Draft)
- **사전 지식:** 기본적인 파일 시스템(폴더, 파일) 및 GitHub Desktop 기본 사용법
- **대상 독자:** 버전 관리 시스템을 처음 접하는 개발자
- **목표 :** 안전하게 독립된 작업 브랜치를 생성하고 원격 저장소(GitHub)에 반영하는 방법 습득
```

## 1. 사전 준비 (최신 상태 동기화)

새 브랜치 생성 전 기준 메인 브랜치(`main` 또는 `develop`) 최신 상태 업데이트

* **GitHub Desktop:** 상단 탭 `Current branch`에서 `main` 선택 후 우측 `Fetch origin` (또는 `Pull origin`) 클릭
* **CLI (터미널):**
  ```bash
  git switch main
  git pull origin main
  ```

## 2. 로컬 브랜치 생성 및 이동

작업 목적에 맞는 이름(예: `feature/login`, `fix/header-bug`)으로 새 브랜치 생성 및 즉시 이동

### 방법 A: GitHub Desktop (GUI 권장)

명령어 입력 없이 직관적인 화면 조작을 통한 브랜치 생성

1. 상단 메뉴 바에서 **`Current branch`** 탭 클릭
2. 드롭다운 메뉴 우측 상단의 **`New branch`** 버튼 클릭 (단축키: `Ctrl + Shift + N` / Mac: `Cmd + Shift + N`)
3. `Name` 입력란에 새 브랜치 이름 입력 후 **`Create branch`** 버튼 클릭
4. 생성 즉시 해당 브랜치로 자동 전환

### 방법 B: 최신 CLI 명령어 (`git switch`)

터미널 환경에서 빠른 브랜치 생성 시 사용하는 표준 명령어

```bash
# 브랜치 생성과 동시에 해당 브랜치로 이동
git switch -c feature/브랜치명
```

## 3. 브랜치 생성 확인

현재 위치한 브랜치가 새로 만든 브랜치인지 확인

* **GitHub Desktop:** 상단 메뉴 바의 **`Current branch`** 표시가 새 브랜치 이름으로 변경되었는지 확인
* **CLI (터미널):** `git branch` 입력 시 `*` 표시가 새 브랜치 앞에 위치하는지 확인

## 4. 원격 저장소(GitHub)에 브랜치 업로드

로컬에 생성된 브랜치를 원격 저장소(GitHub)에 생성 및 연결

* **GitHub Desktop:** 상단 우측 **`Publish branch`** 버튼 클릭 시 원격 저장소 즉시 업로드
* **CLI (터미널):**
  ```bash
  git push -u origin feature/브랜치명
  ```

## 5. 요약 치트시트 (한눈에 보기)

| 단계 | GitHub Desktop (GUI) | CLI (터미널) | 설명 |
| :--- | :--- | :--- | :--- |
| **1. 최신화** | `Pull origin` 클릭 | `git pull origin main` | 기준 브랜치 최신 코드 동기화 |
| **2. 생성/이동** | `Current branch` → `New branch` | `git switch -c [브랜치명]` | 새 브랜치 생성 후 즉시 전환 |
| **3. 원격 반영** | `Publish branch` 클릭 | `git push -u origin [브랜치명]` | 로컬 브랜치 GitHub 업로드 |

## 6. 주의사항 (Best Practices)

* **메인 브랜치 직접 작업 금지:** `main` 브랜치 직접 코드 수정 지양 및 반드시 새 브랜치 생성 후 작업
* **명확한 네이밍 규칙:** 협업 시 목적 파악을 위한 접두사(Prefix) 활용 (예: `feature/기능명`, `fix/버그명`, `docs/문서명`)
