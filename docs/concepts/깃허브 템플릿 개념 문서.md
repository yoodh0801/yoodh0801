# GitHub Template (.github 폴더) 개념 문서

```markdown
- **작성자:** 유동한
- **최종 수정일:** 2026-11-26
- **상태:** 초안 (Draft) / 검토 중 (In Review) / 승인됨 (Approved)
- **사전 지식:** GitHub 기본 개념 (Repository, Issue, Pull Request)
- **대상 독자:** 저장소 관리 및 팀 협업 표준화를 도입하려는 개발자
```

---

## 1. 개요(Overview)
- **정의(Definition):** 저장소 최상단(Root)에 위치하여 Issue, Pull Request 양식 및 CI/CD 워크플로우 등 **GitHub 전용 설정과 표준 문서를 관리하는 특수 숨김 디렉토리**
- **등장 배경(Why it exists):** 팀원마다 제각각인 버그 제보, PR 설명으로 인한 커뮤니케이션 누락 및 코드 리뷰 지연 문제를 해결하기 위해 협업 양식 표준화 필요
- **핵심 비유:** 프로젝트 저장소 내에 비치된 **표준 민원 신청서 양식함 및 자동화 규칙판**

## 2. 핵심 구성 요소(Key Components)
- **`ISSUE_TEMPLATE/`:** 버그 리포트, 기능 제안 등 이슈 생성 시 선택할 수 있는 마크다운(`.md`) 또는 폼(`.yml`) 양식 모음
- **`PULL_REQUEST_TEMPLATE.md`:** PR 생성 시 본문에 자동으로 채워지는 작업 내역, 테스트 여부, 리뷰어 체크리스트 양식
- **`workflows/`:** GitHub Actions를 통해 빌드, 테스트, 배포 등을 자동 실행하는 YAML 설정 파일 보관소
- **`CODEOWNERS`:** 특정 디렉토리나 파일 변경 시 자동으로 코드 리뷰어를 지정해 주는 권한 및 책임 명세 파일

## 3. 동작 원리(How It Works)
저장소 내 `.github` 경로에 정해진 규칙(Convention)대로 파일을 배치하면 GitHub 플랫폼이 이를 자동으로 인식하여 UI와 이벤트에 반영합니다.

1. **템플릿 인식:** 저장소 루트(또는 `docs/` 등)에 `.github` 폴더 및 지정된 파일명 생성
2. **자동 로드:** 사용자가 웹에서 `New Issue` 또는 `New Pull Request` 버튼 클릭 시 해당 템플릿 본문 자동 렌더링
3. **자동화 트리거:** 푸시(Push)나 PR 이벤트 발생 시 `workflows/` 및 `CODEOWNERS` 규칙에 따라 자동 검증 및 리뷰어 할당 실행

## 4. 장단점 (Pros & Cons)
- **장점**
  - **커뮤니케이션 일관성:** 필수 정보(재현 경로, 환경, 체크리스트 등) 누락 방지로 리뷰 및 디버깅 시간 단축
  - **프로젝트 루트 깔끔함 유지:** 협업용 설정 파일들을 `.github` 숨김 폴더 하나로 격리하여 실제 소스코드 구조와 분리
  - **온보딩 효율화:** 신규 참여자나 외부 기여자도 별도 교육 없이 팀의 협업 규칙을 자연스럽게 준수 가능
- **한계**
  - **플랫폼 종속성:** GitHub 전용 규약이므로 GitLab, Bitbucket 등 타 플랫폼 이전 시 별도 마이그레이션 필요
  - **과도한 양식 피로도:** 항목을 너무 복잡하게 설계할 경우, 작성자가 대충 기입하거나 양식을 회피하는 부작용 발생

## 5. 활용 사례 및 안티 패턴 (Use Cases & Anti-patterns)
- **적합 (When to use):** 다수의 팀원이 협업하는 프로젝트, 외부 기여자를 받는 오픈소스 저장소, CI/CD 자동화가 필요한 환경
- **부적합 (When NOT to use):** 혼자 빠르게 실험하는 개인 토이 프로젝트(오버엔지니어링), GitHub 외 타 Git 호스팅 서비스 주력 사용 환경
